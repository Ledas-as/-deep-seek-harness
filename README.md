# dsh-memory-guard · 记忆与操作保护

给 DeepSeek Harness 使用的第三方插件，适配 Windows、DSH **0.2.1-rc.2**。当前版本 **0.2.1**，采用 MIT License，与 DeepSeek 官方无隶属关系。

目的：记住你明确保存的规矩，用中文说明计划和关键进展，让项目内常规操作连续完成，危险和不确定操作再单独确认。

0.2.0 默认启用日常模式，减少 0.1.x 的逐条登记和确认。借鉴 [Codex 的工作区与按需审批方式](https://learn.chatgpt.com/docs/agent-approvals-security)，复用 DSH 已有的沙箱和审批；本插件并未实现 Codex 的完整安全引擎。

## 使用时是什么样子

它应当先在聊天中说：

> 我先检查登录流程，找到原因后修改相关文件，再运行测试验证。

接下来查看、搜索和普通编辑会连续进行。发现关键问题、改变方向或需要你决定时再说明，不每调用一个工具就停下来。若要删除日志或清理目录，再解释具体目标、原因和影响并请求确认。

需要授权时，0.2.1 的确认卡片优先展示“操作”和“影响（模型说明）”，再用一句话提醒风险。参数中明确给出的位置最多展示 3 个，其余数量会提示在详情查看。你可以选择“拒绝执行”或“仅允许这一次”。不会拿整段代码当确认正文。

操作原因、完整位置清单、当前目录、工具能力和完整命令移到 `/guard-detail`，按需查看。授权始终绑定完整工具名和本次原始参数，0.2.1 没有改变权限规则。

## 实际保护规则

- `read`、`read_image`、`glob` 可直接使用，显式敏感文件路径和指向这些路径的本地链接会被拒绝。
- 当前项目内普通 `write`、`edit` 和 `str_replace_editor` 的 `view/create/str_replace/insert` 自动继续，不要求 `guard_plan`。空内容整文件覆盖、无法核对路径、项目外修改和其他编辑器操作仍需确认。
- 自动路径拒绝修改 `.git`、`.agents`、`.codex`、`.dsh`、`AGENTS.md`、`node_modules`、插件自身和记忆记录。路径核对包括新文件的现存父目录与本地链接，不能通过目录链接把自动修改带到项目外。
- 普通的 `ask_user_question` 可直接向你提问，不会为了提问再套一层操作授权。
- 项目内容搜索优先使用 `guard_search`，不用确认。它进行区分大小写的字面量搜索，只读普通文本，跳过敏感文件、隐藏目录、依赖目录、生成目录和符号链接。原生 `grep` 仅在项目内明确的普通文件上自动继续；递归 grep 仍需确认，因为它包含隐藏与忽略文件。
- 一次性 `bash`/`pwsh` 的简单常规命令可在宿主已提供 `read-only` 或 `workspace-write` 沙箱时自动继续：`npm test`、`npm/pnpm run test/lint/typecheck/build/check`、`pnpm test`、`yarn test/lint/typecheck/build/check`、`node --test`、`node --check 相对文件`、`git status`（可附 `--short/--porcelain/--branch`）。不自动放行命令拼接、任意程序、持久 shell、解释器内联代码或显式提权。
- 删除、清理、安装、进程控制、发布、项目外修改、未受限命令和未知工具仍先登记中文说明，再由真人逐次确认。模型不能仅用“测试”或“只读”文字自称安全。
- 常规调用继续经过宿主策略，不会自动批准 DSH 自己的审批；宿主仍可因只读模式、先读后改要求或沙箱限制拒绝执行。
- 模型填写的影响会明确标成“模型说明”；插件另用一句话提醒工具能力可能带来的风险，完整解释保留在详情中。
- 确认只对当前会话、当前目录和完全相同的参数生效一次。拒绝、取消、确认界面不可用或插件重载时停止执行。自动调用也会在最后核对参数、目录和受限沙箱是否改变。
- 最终 `ctx.tools.guard()` 检查会阻止未通过本插件检查的调用。其他普通 policy hook 直接返回 `allow`，不能覆盖这个拒绝。
- 模型不能通过 `plugin_manager` 和已识别的 Cordis 动态插件入口停用自己的保护。用户仍可在扩展管理中手动管理。
- 不会自动清理目录，不提供文件删除工具，不把“自己生成的文件”当作可以随意删除的东西。

## 长期记忆

| 输入 | 效果 |
| --- | --- |
| `/guard` | 查看插件状态、命令和当前有效记忆 |
| `/guard-check` | 使用无副作用的模拟工具，核对实际执行拦截；不读写或删除文件 |
| `/remember 请始终用简单中文解释操作` | 直接保存你输入的内容，仅作用于当前项目 |
| `/remember global 不要自行清理我的文件` | 保存为所有项目共用的记忆 |
| `/forget 完整记忆ID` | 停用一条记忆，保留历史，不删除记录 |
| `/guard-detail` | 查看当前会话最近一次操作确认的完整技术详情 |
| `/guard-history` | 查看最近 20 条经本插件询问的授权结果 |

也可以在聊天中说“记住这条规矩”。模型应调用 `guard_memory_propose`，向你展示要保存的原文，由你确认后才写入。插件不会自动读取旧聊天、导入私人文件或从网页中收集记忆。

在 DSH 图形界面输入带参数的指令时，先输入 `/remember` 或 `/forget`，从弹出的指令列表中选中对应项，再输入内容或 ID。若直接粘贴整行被当作普通聊天，它会走模型的确认流程；不要把模型回复当作指令执行成功的证明，用 `/guard` 核对结果。

默认数据目录是 `%LOCALAPPDATA%\DSH-Memory-Guard`。只有启用插件时才会创建。全部记录追加到 `memory.jsonl`，不会覆盖或自动删除历史。每条记忆最多 1200 字符；当前项目和全局记忆合计最多 80 条、12000 字符。记录总量到 4 MB 时停止写入并报错，不自动清理。

授权记录只保存时间、工具名和结果，不保存完整命令、参数或文件内容。`/guard-detail` 的技术详情仅保存在当前进程内存里。

## 安装

在 DSH 的“扩展管理”中选择添加扩展，输入下面的 GitHub 包地址，安装并启用“记忆与操作保护”：

```text
github:Ledas-as/-deep-seek-harness
```

需要本机已安装 Git，且能连接 GitHub。此地址安装仓库默认分支的内容；需要固定版本时，在地址末尾加 `#完整commitSHA`。

Windows 默认安装位置也可使用 DSH 自带 CLI：

```powershell
& "$env:LOCALAPPDATA\Programs\DeepSeek Harness\resources\runtime\cli\bin\dsh.cmd" plugin --profile desktop add 'github:Ledas-as/-deep-seek-harness'
```

本项目尚未发布到 npm。若 GitHub 安装不可用，可以克隆仓库，在源码目录运行 `npm pack --ignore-scripts` 生成 `.tgz`，再在扩展管理中添加该文件的完整路径。

安装本地包的 CLI 示例；请先把路径换成实际生成的包路径：

```powershell
& "$env:LOCALAPPDATA\Programs\DeepSeek Harness\resources\runtime\cli\bin\dsh.cmd" plugin --profile desktop add 'C:\完整路径\dsh-memory-guard-0.2.1.tgz'
```

该操作会更改 DSH 的扩展配置。安装源码目录同样可行，但不要在安装后移动那个目录。安装包内没有 install 脚本，不新增第三方运行依赖；两个 peerDependencies 复用宿主的 Cordis 和 tools API。若安装器提示另一个 DSH 版本不兼容，请停止，不要强行忽略。

安装后先在一个测试聊天中输入 `/guard`，确认能看到“记忆与操作保护正在运行”。如果命令不存在或扩展管理显示错误，保护没有生效。若提示需要重启，请保存现有工作后自行重启 DSH。

## 验证方法

1. 输入 `/remember 测试记忆：请用中文说明操作`，重新打开一个相同项目的聊天，用 `/guard` 确认记忆仍在。
2. 让它查看一个已知普通文本文件，应可正常查看。
3. 让它通过普通文件编辑工具修改一个专门准备的项目内测试文件，应能直接完成，不逐条登记和弹窗。宿主若要求先读文件，仍须先读。
4. 输入 `/guard-check` 验证不确定工具仍被拦截；无需真的运行删除操作。确需确认的操作应显示中文影响，完整参数按需通过 `/guard-detail` 查看。
5. 用 `/forget` 停用测试记忆，确认 `/guard` 不再加载它；原始历史仍保留。

源码检查：

```powershell
node scripts/check.mjs
node --test test/guard.test.mjs
```

本项目的自动测试不会执行真实 shell 命令或删除文件；只使用隔离的临时数据。不会自动清理测试文件。

## 边界和已知限制

- **不是操作系统沙箱，也不是文件恢复或备份服务。** 它只保护经过 DSH 工具注册表的调用。其他软件、恶意 Host 插件或已经脱离工具运行的进程不受它控制。
- **项目内自动修改允许改变和移除文件中的部分内容。常规任务脚本也能修改、甚至删除沙箱允许范围内的文件。** 本插件不分析项目脚本内部，不提供“所有删除都必定弹窗”的保证。只在信任项目代码时使用日常模式；明确的删除/清理命令仍需额外确认。
- 一旦你批准任意脚本，脚本内部仍可能有未在文字说明中如实描述的行为；本插件没有证明脚本安全的能力。不要把一次确认理解成脚本已通过安全审计。
- 这版要求 **native 工具模式**。纯 PTC 模式只有 `run_code` 入口，会因无法预先登记 `guard_plan` 而被拒绝；请切回 native 模式。它不会为兼容而放宽保护。
- 子代理同样受全局 guard 约束，符合自动规则的操作可以继续。需要确认而宿主不接受子代理直接提问时，该操作会停止，需要主代理处理。
- 任务中的中文进度、开始和完成说明通过系统规范约束模型；普通聊天文本不是代码强制重写。需要授权的操作另有强制中文登记和真人确认。
- 敏感路径和常见凭据格式检查属于有限的防护，无法识别所有秘密。获批脚本、递归搜索或外部工具仍可能接触未识别的内容。
- 宿主没有受限执行器、当前是完全访问模式，或命令不符合简单语法时，命令仍需确认；插件不会自动修改宿主权限。自动搜索最多扫描 2000 个受支持扩展名文件、每文件 512 KB、累计 8 MiB，返回 200 条匹配；不支持正则，达到预算会提示缩小目录。文件在检查之后被其他进程替换等竞态也不属于强沙箱保证。
- 一份记忆目录建议只由一个 DSH 后端进程使用。多个进程各有内存快照，不提供跨进程即时同步。损坏、过大的存储会报错，插件可能无法加载；这时不会显示“保护正在运行”。
- 插件无法阻止用户主动禁用插件或更改其源码。安装、停用和升级后应通过 `/guard` 检查实际状态。

## 开发接口

Host 入口为 `src/index.mjs`。配置接受可选的绝对路径 `dataDir` 和 `mode`（默认 `balanced`；设置 `strict` 恢复逐次确认文件修改和命令）。记忆格式和默认存储目录沿用 0.1.x，无须迁移。`cordis.patch.yml` 插入一个全局插件，要求宿主已有 `tools`、`systemPrompt`、`userQuestions`、`commands`、`workingDirectory` 服务。自动命令额外核对宿主已有的 `shell` 和 `sandboxPolicy` 服务，缺少时退回确认。

模型工具为 `guard_plan`、`guard_memory_list`、`guard_memory_propose`、`guard_search`。`guard_plan.arguments_json` 必须是目标调用的完整 JSON 对象，不做 shell 拼接或自动执行。`guard_search` 接受 `query` 和可选的项目内 `path`；它不启动 shell 或其他程序。

API 核对依据：[DSH 扩展开发说明](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/cookbook/extension-cookbook.md)、0.2.1-rc.2 随附的公共运行库和说明。验证环境和结果见 [VALIDATION.md](VALIDATION.md)。
